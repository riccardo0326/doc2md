# Phase 9 Findings

## Scope

Phase 9 compares `tiered` and `full-vision` on the local benchmark corpus.
The real EDAG OCR baseline is intentionally out of scope for implementation and
is to be run manually in parallel against the same PDF manifest.

The corpus is generated by:

```bash
doc2md bench corpus --external-root C:\Users\rp99480\dev\ai4tc_webapp
```

The command includes committed synthetic fixtures, ignored local samples, and
all PDFs found below the external reference repository without copying them.
At the time of this Phase 9 implementation, the external reference repository
contains no PDF files. The local discovery found 13 PDFs: the six committed
synthetic fixtures plus seven ignored local sample PDFs.

## Method

- Run each selected pipeline with cold cache and identical documents.
- Record `results.csv`, per-page route/method, wall time, calls, and token usage.
- Use `review-sheet` for seeded blind manual quality scoring.
- Use the local Kelpie judge only when the configured model and service are
  available; malformed responses are recorded as `judge_error`.
- Keep the external EDAG OCR result as a parallel human-run comparison, not an
  invented adapter or a committed response.

## Results

The reproducible offline smoke benchmark over the complete 13-PDF local corpus
is recorded at `bench_runs/phase9-corpus/20261023-133515/` (ignored output). It
uses `FakeVisionBackend`, one repetition, and the three implemented pipelines:

| Pipeline | Runs | Average pages | Vision calls | Total tokens | Median wall time (s) |
|---|---:|---:|---:|---:|---:|
| `tiered` | 13 | 2 | 6 | 120 | 0.148 |
| `full-vision` | 13 | 2 | 21 | 420 | 0.226 |
| `docling-only` | 13 | 2 | 0 | 0 | 0.133 |

This is an offline smoke result, not a product quality claim: the real Kelpie
service, approved remote hard adapter, external PDFs, and human scores were not
available in this environment. No PDF bytes or external-model output is
committed.

## Recommendation

The implementation is ready for a controlled benchmark run. A go/no-go product
recommendation requires the real corpus, an approved remote hard adapter,
Kelpie measurements, and the parallel EDAG OCR comparison. Until those inputs
exist, no quality or savings threshold is claimed.

## Risks And Next Steps

- Connect the approved remote hard adapter before scanned-page measurements.
- Run the existing EDAG OCR software manually against the same manifest.
- Record a cold-cache `tiered` versus `full-vision` run directory here.
- Add a real `baseline_current` adapter only after its invocation and token
  reporting contract are supplied.
